# 本版本的交付与验收

2026-10-28。本文把已讨论的要求落实为本版本的执行依据；能力是否已通过仍以规范根 `CURRENT_STATUS.json` 及对应运行记录为准。

## 先继承的现成做法

[Readwise Ghostreader](https://docs.readwise.io/reader/guides/ghostreader/global)围绕当前材料提问、解释选段；[NotebookLM](https://support.google.com/gemininotebook/answer/16179559?hl=en)围绕选定来源回答、按需保存。[Shape Up 的边界方法](https://basecamp.com/shapeup/1.2-chapter-03)要求先限定问题与完成含义。这里采用这些工作方式，接入现有 BiliNote 阅读/保存底座；不借官方介绍声称我方质量或用户收益已被证明。

## 交付承诺

用户选择一个视频或已读取的材料，说明本次要求并给予必要许可，产品提供可阅读、保存、继续提问、修改与下载的结果。要求可以是摘要、理解解释、特定问题、依据材料拟稿或应用建议；例子不是领域或功能全集。

用户不用修复关键错误、找回重要遗漏或重新整理已经委托产品整理的同一批资料，才算该次交付合格。阅读、思考和最终决策仍属于用户。一次用户示例不成为所有人的默认需求。

- 复述保留讲者意思、论证和重要限定。视频出现某说法，不等于该说法已被独立证实。
- 解释可增加明确标为解释用的例子，不能补造视频事实、代码、参数或画面。
- 核验需要适当的独立证据。当前仅有视频材料时，不宣称完成外部核验；有用部分照常交付，必要缺口明确保留。
- 建议区分讲者观点与据此提出的建议；用户条件未知时不伪装个性化。行动计划不是每份成果的固定部分。
- 实际文件、截图或软件执行须由相应能力真实产出；文字大纲、示意图不能冒充这些结果。无法交付且用户拒绝替代时如实说明。

上述可以在同一请求中组合，不要求用户选择分类或替产品挑工具。

## 有限验收

验收绑定原请求、实际来源版本和最终成果，检查以下六项，不用模型自评分或综合分放行：

1. 原要求的必需部分、范围、长度、格式和禁止项得到遵守。
2. 没有改变结论的无据事实、因果倒置、条件遗漏和假确定性。
3. 用途需要的对象、关系、理由或执行依赖已说明；不能只列出名词让用户重新拼接。
4. 结果足以用于本次承诺的目的，用户不必重做已委托的整理或关键修正。
5. 表达有具体作用：短答可结束；图、表、截图按需采用，不能重复增加解码负担或改变关系含义。
6. 正常产品的生成、保存、读回、追问、修改和导出一致；开发者手工救稿须记录，不能当作自动首稿通过。

母版保留来源正文、版本、定位及可用观察，分开来源、识别、推断与建议，供后续复用；不为用户美化内部母版，不建立无实际用途的知识图谱。

## 停止与重开

已保存且技术检查通过，不能代替上述内容验收。反过来，喜欢程度、真实学习效果、长期收益与市场需求没有观察时保留未知，不据此无限增加本版本任务。

本版用明确的一组请求覆盖整篇理解与应用、局部关系解释、轻量结果、必要材料/能力不足、修改与读回。已有合格证据可复用；至少保留一个未经针对性调稿的新请求。只修阻断承诺的缺陷，复查原缺陷及受影响用途。通过后停止，后续只由新要求、反证或必要缺陷重开。

部分交付或正确拒绝是合格的失败处理，不是原任务成功。`available` 表示可以读取，`ready` 表示模型未报告必需缺口，两者都不是语义质量证书；`semantic_quality_approved=false` 保持真实。

## 版本边界

本版本仍是单机产品，使用已有来源、现有模型与现有图文工具。不承诺完整视觉理解、逐字无误转写、独立事实核验、任意文件格式或外部软件执行。来源失败不当作无字幕，未知外部结果不盲重放，权限、所有者、版本、取消及迟到结果围栏保持。桌宠和新产品方向不属于本次交付。
